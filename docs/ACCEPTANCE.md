# Протокол приёмки (этап Э7)

Документ — рабочая форма **Приложения A** спецификации (`docs/PROJECT_SPEC.md`, версия 1.12).
Приёмка проходит на стенде заказчика: реальные кассы, тестовая информационная база 1С,
`msg.exe`, служба под `LocalSystem`. Проверки, которые нельзя выполнить на машине
разработки (§13.3), отмечаются здесь по факту живого прогона.

Как пользоваться:

1. Перед выездом заполните **раздел 1** (предполётная проверка) — это снимает 80 %
   находок «на месте»: несобранный интерфейс, пустой каталог версий 1С, неизвестный порт.
2. На стенде идите по разделам **2–5**, ставя «Факт» (что увидели), дату и того, кто проверял.
3. Любое расхождение — в **раздел 6** («Замечания»), даже если оно лечится на месте:
   по нему потом правится `docs/RUNBOOK.md` или спецификация.

Обозначения: **ФН1** — загрузка → проверка → слияние → обновление БД; **ФН2** — рассылка
файла по ссылке; **ФН3** — уведомления пользователям.

## 1. Предполётная проверка (до выезда и на месте)

Отчёты сохраняются в файл и прикладываются к протоколу. Ни один пункт `ОШИБКА` не должен
остаться до начала раздела 2 — иначе приёмка превращается в развёртывание.

| Что проверяем | Команда | Отчёт | Факт (дата, кто) |
|---|---|---|---|
| Сервер: БД, схема, миграции, SPA, администраторы, порт, каталоги логов | `python -m server.cli preflight --json > preflight-server.json` | файл | |
| Касса: конфиг, доступность сервера, `1cv8.exe`, `msg.exe`, порт, каталоги, учётные данные 1С | `MagazAgent.exe preflight --json > preflight-store-N.json` | файл | |

`--json` выводится ASCII-экранированным (`\uXXXX`), поэтому файл читается любым
потребителем JSON независимо от кодировки консоли. Текстовый вывод (без `--json`)
рассчитан на глаз и печатается в cp1251-консоли.

Пункты `ВНИМАНИЕ` — не блокируют, но каждый надо объяснить в разделе 6:

- «Дублирующий канал msg.exe не найден» — штатно для Windows Home и политик (R2);
  основной канал — TrayAgent.
- «Ключи шифрования отсутствуют» — на боевом сервере означает, что ключ надо
  восстановить из бэкапа, иначе пароли 1С не расшифруются (§8.3).
- «Пароль не доставлен» — учётные данные придут push-ом после старта агента (§7.2).

### 1.1 Живой прогон без 1С: что уже снято с подозрений

Часть проверок стенда не требует: канал «сервер ↔ агент», доставку учётных данных и показ
уведомления пользователю можно прогнать на машине разработки, подняв настоящий агент на
`127.0.0.1`. Такой прогон выполнен **14.10.2026** (Windows, сервер `http://127.0.0.1:8080`,
агент `python -m client.agent run --config … --console`, магазин с IP `127.0.0.1`):

| Проверка | Чем подтверждено | Факт |
|---|---|---|
| Канал и токен магазина (§8.1) | `GET /health` агента с токеном из карточки | `200`, версия агента `1.0.0`; без токена — `401` |
| Фильтр IP источника (§8.1) | `POST /api/v1/agent/health` с `X-Forwarded-For: 10.9.9.9` | `403` |
| Д-3 «Проверить сейчас» | запрос сервера к живой кассе | `200`, задержка 425–470 мс, `busy` и список сессий приходят |
| Мониторинг (§3.3) | магазин без ручных действий | `is_online = true`, `last_seen_at` обновляется |
| П-1: учётные данные 1С | `PUT /stores/{id}/credentials` → push на кассу | профиль на кассе: версия `1 → 4`, `password_enc` заполнен |
| I-7: пароль не в файлах кассы | поиск строки пароля в `agent-config.json` | не найдено |
| `check_files` через диспетчер | «Проверить файлы» из карточки | задача `success`, сообщение «Файлы «update»: ничего не найдено» |
| ФН3: доставка и «Ознакомлен» | `--pending` → `--ack <id>` в сессии | строка `#N [important] Э7: живой прогон`; на сервере `acknowledged: 1`, `percent: 100`, состояние `done` |
| Очередь уведомлений переживает перезапуск (§7.4) | перезапуск агента | неподтверждённое уведомление дождалось нового запуска |
| Сборка релиза и работа **собранных** exe | `deploy\build_release.bat --skip-ui` → `dist\release\`; затем Д-3 и уведомления через `magaz-agent.exe` и `MagazTrayAgent.exe` | `dist\release\`: 2 exe + 3 файла; Д-3 к exe-агенту → `200`, версия `1.0.0`; `--pending` показал `#N [important]`, `--ack N` → `acknowledged: 1`, `percent: 100`; `magaz-agent.exe preflight --no-server` → 5 OK, 1 `ВНИМАНИЕ` (порт занят живым агентом), 1 `ОШИБКА` (нет 1С — ожидаемо) |
| Переиспользование имени и IP после «Отключить» (Э8, Д-11) | создать магазин → «Отключить» → создать заново с тем же IP и именем | создаётся новая запись (`200`); конфликт остался только с **активным** магазином: повтор активного имени → `422` «уже существует (занято активным магазином)» |
| Конфиг агента в любой момент (Э8, Д-12) | карточка магазина → «Конфиг» → «Скачать agent-config.json» | тот же блок, что при создании: `store_id`, `server_url`, токен, порт, профиль 1С без пароля; браузер реально скачал файл — именно его кладут на кассу |


Что по-прежнему требует стенда (§13.3, разделы 2–5): сам `1cv8.exe` (слияние, обновление БД,
`taskkill`, снятие блокировок), окно `msg.exe` на рабочем столе кассира, установка службы
`MagazAgent` на кассу и её старт после перезагрузки (сам дистрибутив уже собирается и проверен:
см. отчёт по Э7 в `README.md`).
Доработки Э8 (Д-11, Д-12, Д-13) тоже пройдены живьём на сервере разработки — они перечислены
строками выше и отдельного прогона на стенде не требуют; на кассе стоит лишь убедиться, что
`agent-config.json` взят из карточки свежим (после любой правки магазина или перевыпуска токена
файл перечитывается кнопкой «Конфиг»).
В прогоне проверялся только тост TrayAgent: системного окна `msg.exe` больше нет
(спека 1.22 — единственный канал показа), поэтому дублирующий показ проверяется
на кассе вместе с тостом (§4.4).

Повторить прогон можно на одной машине (1С не нужна):

```powershell
python -m server.main                                        # сервер: http://127.0.0.1:8080
python -m server.cli create-admin --username e7 --password <пароль>
# магазин с IP 127.0.0.1; из ответа POST /admin/stores взять agent_config.config_json
python -m client.agent run --config .\agent-config.json --console
python -m client.tray --pending                              # что ждёт «Ознакомлен»
python -m client.tray --ack <id>                             # «Ознакомлен» из текущей сессии
```
